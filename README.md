# genorg.ru — сайт ДИЭН-Системс

Сайт компании «ДИЭН-Системс» (аренда дизельных генераторов, ПЭС,
компрессоров, кранов-манипуляторов; продажа техники б/у).

**Next.js 15 + Strapi 5.** Весь контент и все фотографии лежат в CMS —
редактор правит сайт, не трогая код. Адреса страниц унаследованы от
боевого сайта один в один, поэтому переезд на новый движок не сбил
позиции.

| | |
|---|---|
| Стек | Next.js 15.5 (App Router) · React 19 · TypeScript 5.7 · Strapi 5.62 |
| CMS | Strapi 5.62 — SQLite локально, PostgreSQL в проде |
| Сборка | 101 страница статически, ISR 60 с |
| Адресов | 90 URL в sitemap, 91 legacy-URL перенесены |
| Контент | 47 позиций · 19 статей · 9 объектов · 14 страниц · 27 текстовых блоков · 25 пунктов меню |
| Медиа | 62 файла в медиатеке Strapi |
| Проверки | 16 скриптов, все зелёные на текущем коммите |

## 1. Быстрый старт

### Локально (без Docker)

Нужен Node 22. Docker на машине разработки может быть недоступен —
локально всё работает на SQLite.

```bash
cd variant-c
npm install

# CMS: зависимости, схемы, база, админка, токены, менеджеры
cd cms-admin && npm install && cd ..
node scripts/deploy-schemas.mjs      # схемы из cms/schemas → cms-admin/src/api
node scripts/bootstrap-strapi.mjs    # админ + API-токены + менеджеры
npm --prefix cms-admin run develop   # CMS на :1337

# снимок CMS — страховка на случай, если CMS недоступна
node scripts/export-snapshot.mjs     # → content/snapshot.json (в .gitignore)

# в отдельном терминале
npm run dev                          # сайт на :3100
```

| Адрес | Что это |
|---|---|
| http://127.0.0.1:3100 | сайт |
| http://127.0.0.1:1337/admin | админка CMS |
| http://127.0.0.1:3100/admin | короткая ссылка на админку CMS (редирект) |

Переменные окружения — в `variant-c/.env` (в `.gitignore`), образец —
`.env.example`.

```bash
STRAPI_URL=http://127.0.0.1:1337
STRAPI_TOKEN=…               # из .strapi-tokens.json
CMS_PUBLIC_URL=http://127.0.0.1:1337   # публичный адрес CMS для ссылок на фото
SITE_URL=https://genorg.ru
```

### На сервере (Docker)

```bash
git clone git@github.com:scorpik90/diensistems.git
cd diensistems/variant-c
./deploy/deploy.sh
```

Скрипт идемпотентен: создаёт `.env` со случайными секретами, поднимает
PostgreSQL, Strapi и Next.js за Caddy с авто-SSL, импортирует данные,
создаёт админа и менеджеров, настраивает ежедневные бэкапы.
Подробности — в [`deploy/README.md`](deploy/README.md).

### Один catch-all вместо 91 маршрута

Боевой сайт использовал **плоские односегментные адреса**
(`/arendadizelnogogeneratora100kvt`, `/arendapes60kvt`,
`/kompressornasmeny330`). В App Router плоский URL возможен только через
catch-all — вся маршрутизация живёт в `app/[...slug]/page.tsx`, а тип
контента определяется по данным CMS.

**Меняем движок, не меняем адреса** → риск падения позиций ≈ 0.

Страницы живут в ISR (`revalidate = 60`), `dynamicParams` не ограничен:
запись, добавленная в CMS после сборки, рендерится по первому запросу
и дальше кэшируется. Публикация новой позиции, статьи или редиректа
работает **без `next build`**.

## 3. Strapi — CMS

### Что это

**Strapi 5.62** — headless CMS, в которой лежит всё содержимое сайта.
Фронтенд (Next.js) обращается к ней по REST API и не хранит
контент у себя.

CMS — единственный источник правды:

* **все тексты**, которые видит посетитель;
* **все фотографии** — в медиатеке;
* **каталог, статьи, объекты, страницы, прайс-листы, отзывы**;
* **меню** сайта;
* **заявки** посетителей.

Что осталось в коде — логика: фильтры, расчёты цен, вёрстка.

### Как запустить и зайти

```bash
npm --prefix cms-admin run develop      # http://127.0.0.1:1337/admin
```

Локально CMS работает на SQLite (`cms-admin/.tmp/data.db`), в проде —
на PostgreSQL. Схемы лежат в `cms/schemas/*.json` и разворачиваются
скриптом:

```bash
node scripts/deploy-schemas.mjs    # cms/schemas → cms-admin/src/api
```

После изменения схемы Strapi нужно перезапустить.

### Учётные записи

| Роль | Логин | Что может |
|---|---|---|
| Super Admin | `admin@genorg.ru` | всё, включая настройки и пользователей |
| Editor | `editor@genorg.ru` | контент: каталог, статьи, объекты, страницы, тексты |
| Author | `author@genorg.ru` | свои статьи |

Пароли лежат в `.env` (в `.gitignore`) и в файле
`ДИЭН-Системс — доступы к CMS.txt` на рабочем столе владельца.
Пересоздать файл: `node scripts/_save-credentials.mjs`.

Смена пароля: **Settings → Users → [пользователь] → Reset password**.
Новый менеджер: **Settings → Users → Create new user** → выбрать роль.
Роли: **Settings → Roles**.

### Текстовый блок — главная сущность для редактора

Один блок = один смысловой экран. В нём:

| Поле | Что в нём |
|---|---|
| `key` | машинный ключ: `home.hero`, `header.main`, `catalog.main`, `product.main`, `contacts.main`, `calc.main`, `form.main`, `cookie.main`, `errors.main`, `seo.main`… |
| `group` | раздел: global, header, footer, home, catalog, product, contacts, cases, articles, forms, seo |
| `items` | структура блока: заголовки, тексты, списки, кнопки — в виде JSON |
| `title` | человеческое название блока (для поиска в списке) |

Пример `home.hero` → `items`:

```json
{
  "eyebrow": "Японское оборудование AIRMAN и DENYO",
  "h1Before": "Аренда генераторов",
  "h1Price": "от {minPrice} ₽{priceUnit}",
  "h1After": "с доставкой за 2 часа",
  "lead": "Собственный парк дизельных электростанций на {fleetMW} МВт — от 8 до 800 кВт…",
  "btnPrimary": "Подобрать мощность за 30 секунд",
  "btnSecondary": "Смотреть каталог из {count} {modelWord}",
  "factLabels": ["собственный парк", "доставка по Москве", "на рынке с {foundedYear}"]
}
```

### Пункт меню

`group` (`header` / `tech` / `footer-services` / `footer-company`),
`label`, `href`, `note` (пояснение под названием в мега-меню), `order`.

### Медиатека

Фотография позиции, объекта, логотип, знак и фон первого экрана —
в медиатеке Strapi. Поля `equipment.image` и `case.image` — типа
**media**, у настроек сайта — `logo`, `logoMark`, `heroImage`.

При загрузке Strapi создаёт уменьшенные копии (thumbnail / small /
medium / large); сайт отдаёт `<img srcset>` — браузер сам выбирает
подходящий файл.

Ссылки на фото строятся по `CMS_PUBLIC_URL` — публичному адресу CMS.
Внутри контейнеров CMS доступна по `http://strapi:1337`, а браузеру
посетителя нужен внешний (`https://cms.genorg.ru`).

### Перенос контента

```bash
node scripts/import-to-strapi.mjs --reset   # каталог, статьи, кейсы, страницы, прайс
node scripts/import-content-to-cms.mjs      # текстовые блоки, меню, медиатека
node scripts/import-body-images.mjs          # фотографии внутри текстов
```

Скрипты идемпотентны: повторный прогон обновляет записи, а не создаёт
дубликаты. `--clean-media` перезаливает медиатеку с нуля.

### Если CMS упала

Сайт не отдаёт 500: адаптер `ResilientCMS` (`lib/cms.ts`) переключается
на снимок `content/snapshot.json` и пишет предупреждение в лог. Отдельного
«mock-режима» с локальным редактором больше нет — CMS единственный
источник правды, а снимок лишь страховка на время аварии. Снимок
генерируется из живой CMS (`node scripts/export-snapshot.mjs`), вручную
не ведётся и в репозиторий не попадает. Обновлять его после крупных
правок контента и обязательно перед деплоем.

## 4. Как редактировать сайт

Типичные задачи редактора — без единой строчки кода.

**Поменять цену или описание техники**
Content Manager → *Позиция каталога* → нужная позиция → «Цена» или
«Описание». Изменение доезжает до сайта за минуту (ISR 60 с).

**Поменять заголовок раздела**
Content Manager → *Текстовый блок* → найти по `key` (например
`home.catalog`) → поле `items` → изменить нужный ключ.

**Добавить пункт в меню**
Content Manager → *Пункт меню* → Create new entry → group, label, href,
order.

**Поставить фото**
Content Manager → *Позиция каталога* → поле «Фото» → загрузить файл
или выбрать из медиатеки.

**Добавить статью или объект**
Content Manager → *Статья* / *Объект* → Create new entry → slug
(латиницей), заголовок, текст.

**Добавить редирект с прежнего адреса**
Content Manager → *301-редирект* → from / to.

**Что вставлять в поля с подстановками**
См. раздел 5 — редактор может писать `{price}` и `{count}`, числа
подставятся сами.

## 5. Подстановки в текстах

В текстах CMS можно использовать метки — числа берутся из каталога и
настроек, поэтому текст остаётся живым: меняется цена — меняется
предложение, без правки формулировки.

**Серверные** (подставляет `lib/tokens.ts`):

| Метка | Значение |
|---|---|
| `{count}` | число моделей в категории |
| `{countWord}` | вид / вида / видов |
| `{modelWord}` | модель / модели / моделей |
| `{powerRange}` | «от 8 до 800 кВт» |
| `{minPrice}` | минимальная цена: «2 000» |
| `{priceUnit}` | `/сутки` или `/смена` |
| `{priceLong}` | «в сутки» или «за смену 8 часов» |
| `{delivery}` | «от 2 часов» |
| `{brands}` | список брендов: «Airman, Denyo, Cummins» |
| `{fleetMW}` | мощность парка, МВт |
| `{discountPercent}`, `{discountFromDays}` | скидка и срок аренды для неё |
| `{foundedYear}`, `{years}`, `{year}` | год основания, сколько лет на рынке, текущий год |
| `{company}`, `{legalName}` | название и юридическое лицо |
| `{phone}`, `{email}`, `{address}`, `{workingHours}` | контакты |
| `{deliveryHours}` | срок доставки, часов |

**Клиентские** (подставляет компонент в браузере):

| Метка | Значение |
|---|---|
| `{headroom}` | запас мощности в процентах (зависит от сценария) |
| `{model}`, `{kw}`, `{days}`, `{price}` | модель, мощность, срок, цена — в форме заявки |
| `{brand}`, `{brandCount}`, `{itemWord}` | бренд, число позиций бренда, слово «позиция/позиции/позиций» |

Неизвестная метка заменяется пустой строкой, но **клиентские**
сохраняются — их наполняет браузер. Проверка:

```bash
node scripts/_check-placeholders.mjs
```

## 6. Модель данных

Боевая CMS (PHP) использовала отдельный шаблон для каждой категории:
ДГУ, ПЭС, компрессоры, компрессоры на смену, манипуляторы, продажа
б/у. В headless это **одна сущность** `equipment` с дискриминатором
`category`:

```ts
interface Equipment {
  slug: string;            // legacy-URL без ведущего слэша
  category: 'generator' | 'pes' | 'compressor'
          | 'compressor-shift' | 'manipulator' | 'used';
  title: string;
  model: string;           // Airman SDG150 / HINO 500 / …
  brand: string | null;
  power: number | null;    // кВт / м³/мин / т
  powerUnit: string;
  price: { value: number; unit: string } | null;   // 2 000 ₽ /сутки
  specGroups: { group: string; rows: { label: string; value: string }[] }[];
  image: CmsImage | null;  // медиатека Strapi
  description: string;
  legacyUrls: string[];    // источник 301-редиректов
}
```

Следствие: **добавление новой категории = одна запись в CMS**, а не
новый шаблон на фронте.

## 7. Каталог и фильтры

Один компонент обслуживает витрину на главной и полный каталог.

* **Фильтр по бренду** — из адресной строки (`?brand=Airman`); ссылки
  на бренды в шапке и в полосе логотипов ведут в каталог.
* **Ось мощности — своя для каждой категории:**
  электростанции → кВт, компрессоры → м³/мин (производительность),
  манипуляторы → т (грузоподъёмность).
* Порядок вывода: сначала позиции с меткой «Хит аренды», потом
  «Новинка», остальные — по возрастанию мощности.

Счётные слова и единицы измерения берутся из данных, а не из
списка категорий: «5 видов кранов-манипуляторов», «2 единицы техники».

## 8. SEO и GEO

Цель: первые результаты по релевантным запросам — и в обычном поиске
(Яндекс, Google), и в генеративной выдаче (ЯндексGPT, Алиса, ChatGPT,
Perplexity, Claude).

**Что сделано**

* **Sitemap** — генерируется из CMS, 90 уникальных URL, `lastmod` из
  даты изменения записи.
* **Мета-теги** — собираются кодом (`lib/seo-meta.ts`,
  `lib/product-meta.ts`), а не берутся из legacy «как есть»: длинные
  заголовки обрезаются по границе слова, короткие служебные
  дополняются уточнением.
* **Структура** — `h1` и `h2` на всех страницах, `canonical`,
  `lang="ru"`.
* **Разметка** — `Organization` + `LocalBusiness`, `Product` с ценой и
  характеристиками, `BreadcrumbList`, `FAQPage`, `ItemList`.
* **JSON-LD** собирается через `jsonLd()` — эскейп `<` не даёт строке
  из CMS закрыть тег `<script>`.
* **Блок «краткий ответ»** на страницах категорий — первый абзац
  прямым ответом, дальше факты отдельными строками.
* **`public/llms.txt`** — карта сайта в текстовом виде для
  генеративных поисковиков (стандарт llmstxt.org), генерируется
  `node scripts/make-llms-txt.mjs`.
* В `robots.txt` разрешены GPTBot, OAI-SearchBot, ChatGPT-User,
  PerplexityBot, ClaudeBot, Google-Extended, Applebot-Extended, Yandex.

Проверки: `node scripts/_seo-headings.mjs`, `node scripts/_seo-geo-check.mjs`.

## 9. Заявки

Форма на главной и в карточке товара. Кнопка «Заказать» ведёт на
форму заявки и **предзаполняет** её: тема («Что требуется») — по
категории техники, комментарий — модель и мощность.

Куда попадает заявка:

1. **CMS** — коллекция «Заявка» (основное хранилище, видно в админке);
2. боевой эндпоинт `/sendfeed/` — пока жив боевой сайт;
3. CRM-webhook, если задан `CRM_WEBHOOK_URL`;
4. файл `data/leads.ndjson` — резервный канал, если CMS недоступна.

Требования к форме: honeypot-поле (боты его заполняют), rate limit
`LEADS_RATE_LIMIT` (по умолчанию 5 заявок в час с одного IP), валидация
имени и телефона, CORS-заголовки выдаются **только** при заданном
`ALLOWED_ORIGIN`.

## 13. Безопасность

* **Санитизация HTML.** Поля `bodyHtml` перед рендером проходят
  allowlist-фильтр (`lib/sanitize.ts`): остаются только разрешённые
  теги и атрибуты, `on*` и схемы `javascript:` / `data:` вырезаются.
  Разметка legacy-страниц (colspan/rowspan прайса, классы)
  сохраняется.
* **JSON-LD** собирается через `jsonLd()`.
* **Токен сборки** (`STRAPI_TOKEN`) передаётся в образ как BuildKit
  **secret**, а не как `ARG`: аргументы сборки сохраняются в истории
  образа, секрет — нет.
* **Одна точка правки контента.** Локального редактора и mock-режима
  нет: `/admin` — редирект в админку CMS. Запись идёт только через
  Strapi с его ролями и историей изменений.
* **Пароли не в коде.** `create-managers.mjs` берёт их из переменных
  окружения; `.env`, `.env.local`, `.env.production`,
  `.strapi-tokens.json`, `secrets/` и `data/` — в `.gitignore`.
* Перед отправкой в GitHub проверяется индекс:
  `node scripts/_check-secrets.mjs`.

## 15. Ограничения

* Локально Docker может быть недоступен — CMS тогда работает на SQLite
  и запускается через `npm --prefix cms-admin run develop`.
* В `develop` Strapi на некоторых машинах периодически падает; на
  сервере он работает в `production`. Локально помогает сторож:
  `node scripts/_watch-strapi.mjs`.
* Письма с форм уходят через цепочку боевого сайта, пока он жив; для
  собственных писем нужен внешний SMTP (Mail.ru, Яндекс.360).
* Медиатека в проде — том Docker (`strapi-uploads`), при переезде
  сохранять его или перезаливать через `import-content-to-cms.mjs`.

Что нашлось при переносе с боевого сайта и как это исправлено —
в [`docs/migration-notes.md`](docs/migration-notes.md).
