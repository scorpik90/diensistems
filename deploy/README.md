# Деплой genorg.ru

Скрипт `deploy.sh` поднимает на сервере весь стек: **сайт** (Next.js 15),
**CMS** (Strapi 5), **PostgreSQL** и **Caddy** (reverse proxy с бесплатным
SSL-сертификатом).

```
./deploy/deploy.sh
```

Скрипт идемпотентный — его можно запускать повторно, он ничего не ломает.

---

## Что нужно сделать руками

Автоматизировать эти пункты нельзя — они требуют вашего участия.

| # | Шаг | Как |
|---|---|---|
| 1 | **Купить сервер** | REG.RU → Рег.облако: 2–4 ядра, 4 ГБ RAM, 40–80 ГБ NVMe, Ubuntu 24.04. Оплата картой РФ. Положите free-tier VPS (2 ядра / 4 ГБ на 2 месяца), чтобы обкатать бесплатно. |
| 2 | **Прописать домен** | A-запись `genorg.ru` → IP сервера. Для админки — `cms.genorg.ru` → тот же IP. |
| 3 | **Залить код** | `git clone <репозиторий> /opt/genorg` (или скопировать архивом). |
| 4 | **Запустить деплой** | `cd /opt/genorg && chmod +x deploy/deploy.sh && ./deploy/deploy.sh` |
| 5 | **Зайти по SSH и открыть порт** | Если firewall закрывает 80/443: `ufw allow 80/tcp && ufw allow 443/tcp` |

Шаги 1–5 — один раз. Дальше обновления: залить изменения и запустить
`./deploy/deploy.sh` снова.

---

## Что делает скрипт

1. **Проверяет окружение** — Docker и Compose, занятость портов 80/443.
2. **Создаёт `.env`** со случайными секретами (пароль БД, ключи Strapi,
   токен API). Файл не перезаписывается при повторном запуске. Секрет
   сборки сайта кладётся в `secrets/strapi_token.txt` — он монтируется
   как BuildKit secret и в историю образа не попадает.
3. **Поднимает PostgreSQL** и ждёт готовности.
4. **Собирает и запускает Strapi**, ждёт ответа CMS.
5. **Импортирует данные** — 47 позиций каталога, 19 статей, 9 объектов,
   14 страниц, прайс-листы, отзывы с Яндекс.Карт.
6. **Собирает и запускает сайт.** Сборка идёт *после* старта CMS: страницы
   генерируются из данных (`generateStaticParams`), и без CMS сборка
   не найдёт контент.
7. **Поднимает Caddy** — сам выпускает сертификат Let's Encrypt, как только
   домен начнёт указывать на сервер.
8. **Создаёт учётные записи менеджеров** в CMS и печатает логины с паролями.
9. **Настраивает ежедневные бэкапы** — дамп БД, загруженные файлы и
   резервные заявки (`data/`) в `/opt/genorg-backups`, ротация 14 копий.

## Что останется после деплоя

* Сменить пароли менеджеров в админке.
* Проверить форму заявки: заявки сохраняются в CMS («Content Manager → Заявки»),
  дублируются на боевой эндпоинт `/sendfeed/` (почтовая цепочка старого сайта)
  и в CRM, если задан `CRM_WEBHOOK_URL`. Прямого SMTP в коде пока нет —
  после отключения боевого сайта подключите внешний SMTP (Mail.ru,
  Яндекс.360) в `/api/leads`. Резервный файл заявок (`data/`) включён
  в ежедневный бэкап.
* Добавить сайт в Яндекс.Вебмастер и в Яндекс.Карты (нужен подтверждённый
  домен и почта на нём).
* Обновить `SITE_URL` в `.env`, если домен отличается от `genorg.ru`.
* Проверить `CMS_PUBLIC_URL` в `.env` — это публичный адрес CMS
  (`https://cms.genorg.ru`). От него строятся ссылки на фотографии
  в вёрстке; внутренний адрес контейнера (`http://strapi:1337`)
  браузеру посетителя недоступен. Если поменять адрес CMS —
  поменять и его, и пересобрать сайт (`docker compose up -d --build web`),
  иначе в собранных страницах останутся старые ссылки на фото.

## Где лежат фотографии

Все снимки — в медиатеке Strapi (том `strapi-uploads`), сайт берёт их
оттуда. В репозитории остался только архив исходников
`assets/legacy-images/` — он нужен для перезаливки, сайт его не
раздаёт.

Фотографии отдаются с домена CMS (`cms.genorg.ru/uploads/…`).
Дополнительно Caddy проксирует `/uploads/*` и с домена сайта — если
захотите переключить ссылки на `genorg.ru/uploads/…`, достаточно
поменять `CMS_PUBLIC_URL` и пересобрать образ.

## Структура

```
docker-compose.yml        сервисы: db, strapi, web, caddy
deploy/
  deploy.sh               главный скрипт (идемпотентный)
  Dockerfile.web          образ сайта (Next.js)
  Dockerfile.strapi       образ CMS (Strapi)
  Caddyfile               маршрутизация и авто-SSL
```

| Адрес | Назначение |
|---|---|
| `https://genorg.ru/` | сайт |
| `https://cms.genorg.ru/admin` | админка CMS |
| `127.0.0.1:1337` | CMS напрямую — только через SSH-туннель |

Админка намеренно не выставлена наружу: порт 1337 слушает только
localhost, снаружи доступ к ней идёт через Caddy с доменом `cms.genorg.ru`.
Если нужен доступ по IP — пробросить порт вручную в `docker-compose.yml`.

## Обслуживание

```bash
cd /opt/genorg

docker compose ps                 # состояние сервисов
docker compose logs -f web        # логи сайта
docker compose logs -f strapi     # логи CMS
docker compose restart strapi     # перезапустить CMS
docker compose down               # остановить всё (данные в томах сохранятся)

/opt/genorg-backups/backup.sh     # ручной бэкап
cat /opt/genorg-backups/backup.log
```

## Проверка конфигурации без сервера

```bash
node scripts/_check-deploy.mjs
```

Скрипт сверяет `docker-compose.yml` с `deploy.sh`: наличие всех сервисов,
все ли переменные окружения генерируются, правильный ли порядок шагов
(сборка сайта — после старта CMS), открыты ли нужные порты и не торчит ли
админка наружу.
